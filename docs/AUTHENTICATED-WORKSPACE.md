## October 6 operational increment

This section supersedes the historical synthetic-workspace scope below. The owner authorized ordinary empty workspaces, an initial invitation and empty **Quartermaster** workspace, and inaccessible backup copies until expiry with deletion replay. Account credentials and temporary invitation passwords are never stored in this public repository. Deployment evidence is maintained in `IMPLEMENTATION.md`; source implementation alone is not proof of a completed rollout.

The responsive client now connects assets and lifecycle/financial details, hierarchical locations, extensible asset types, components/access constraints, tasks/readings, recurring plans/work logs, policies/valuations, incident snapshots/assessments, management-accounting reports, previewed business rules, saved searches, portable ZIP/CSV/print exports, private photo capture, voice-assisted drafts, job status/retry, team invitations/capabilities, workspace settings and deletion. No sample assets are seeded. Disabled buttons indicate validation, permissions or in-flight work, not roadmap placeholders.

The API adds `/records/{kind}`, `/media/uploads`, `/media/{id}/{renew,complete,url,intent,analyze}`, `/conversations/{id}/{transcribe,turns,commit}`, `/reports`, `/exports`, `/jobs/{id}/{retry,download}`, `/members`, `/invitations`, `/settings`, bodyless DELETE routes for assets/records/photos/drafts/conversations, and `POST /tenant/delete` with the typed workspace-name confirmation. Consult source routes for exact methods. Ten capabilities replace the original four. Financial edits, rule activation, exports and administration are separately authorized; destructive/admin/export actions require authentication within 15 minutes. Use **Sign in again in a new tab**, then **Refresh session**. Forms retain uncertain saves for retries with the same key and version.

The shared browser API client hashes every write's exact UTF-8 body into `x-amz-content-sha256`, including empty-body logout and deletion, while preserving CSRF/idempotency/version headers. Payload signing is required for [CloudFront origin access control of the private Lambda URL](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-lambda.html); an unsigned body can be rejected before reaching application logs. Live checks also found that DELETE with a JSON body fails signature validation, so the client rejects nonempty DELETE input and uses the explicit POST action for workspace confirmation. Browser regression tests check the checksum on every write. Capture prompt v2 includes the actual bounded JSON schema, and invalid model output fails closed without writing an asset.

Photo uploads use a checksum-bound, size/type-limited private S3 POST grant, pinned object versions, decoded-format verification, a 24-megapixel/12-MB limit and stripped-metadata JPEG display images (maximum 2400 pixels). JPEG, PNG and WebP are accepted; HEIC files must be converted or taken through a browser camera that supplies JPEG. Display URLs expire in 60 seconds; **Refresh photo** obtains another. Original bytes expire after 15 days. Resized photos have no age-based expiry. Deleting an asset also purges photo versions and invalidates cached export packages.

Voice is foreground push-to-talk: up to 20 seconds of mono 16-kHz PCM stays in memory, is sent to the BFF, and is transcribed through AWS streaming speech. Raw audio is not stored. Review/correct the transcription before sending it to the assistant. Microphone tracks stop on interruption, navigation or loss of connectivity. Optional spoken replies use the device's speech service and disclose that provider boundary. AWS Nova 2 Lite uses only the approved US inference-profile destinations. It proposes bounded JSON, never SQL or authorized writes; **Apply proposal**, edit the review and explicitly confirm before atomic asset/components/tasks/readings/photo attachment. Server-saved review data survives sign-out; unsaved browser input does not. Transcripts and unaccepted proposals expire after 15 days.

SQS drives an ARM64 Lambda worker with native image decoding, two-concurrent/180-second bounds, durable leases, capability rechecks and a dead-letter alarm. Scheduler creates one-time expiry/maintenance tasks only; there is no recurring idle database poll. Daily admission limits are 100 AI requests and 900 voice seconds both globally and per tenant; failed attempts consume admission. These are cost guardrails, not a promise that total AWS charges cannot exceed the $100 budget. Exports contain up to 100 assets per part, bounded associated records and 100 MB including photos, with checksums and an explicit next cursor. Accounting is completed-month straight-line management estimation, not tax advice or general-ledger posting. An incident snapshots the recorded scope at creation, not a reconstructed historical estate.

### Operational rollout and recovery commands

Use Node 24 and the pinned pnpm version. Run `pnpm verify`, `pnpm infra:check`, `pnpm test:e2e` and dependency audit. Review fresh Terraform plans and policy checks before applying foundation/delivery changes. The database migration is operator-only, not part of the public build role. Never edit applied migrations 0001–0003; 0004 adds the operational tables/policies.

Operator commands use `QM_EXPECTED_ACCOUNT_ID` and `QM_OPERATOR_CONFIRM=quartermaster-dev:<command>` with the explicit `default` profile. Run `migrate`, initialize the new `worker-credentials`, then `check`, `worker-check` and `integration`. Do not rotate the established application credential as part of this increment. Push the validated commit to `dev` to release both immutable API and worker versions through CodePipeline; deployment checks both before moving live aliases and restores prior aliases/index on failure.

After release, run `QM_EXPECTED_RELEASE=<commit> node tools/verify-workspace.mjs`, and the operator `cloud-check`. The latter creates fresh isolated tenant IDs and short-lived test sessions, exercises the actual public API/S3/SQS/worker/Bedrock/Transcribe/export/purge boundaries, and removes its fixture rows, sessions, live media and schedules. It never creates a Cognito identity and does not prove human MFA enrollment, microphone hardware or speech accuracy. Keep failure evidence content-free. Monitor API/worker failure, dead-letter and backup-failure alarms at the configured operations recipient.

The initial `invite` command is restricted to the approved recipient and workspace name, with a protected, stable `QM_TENANT_ID`, `QM_INVITE_EMAIL`, `QM_TENANT_NAME`, and `QM_USER_POOL_ID`. It emails through Cognito and creates an empty ordinary workspace with owner capabilities. The human sets the permanent password and TOTP; the operator must not handle those secrets. Additional users are invited from Team. Membership revocation takes effect on the next API/database request; the last administrator cannot be removed.

For restore, create an isolated private cluster and media bucket with the `quartermaster-dev-restore-*` names required by `restore-admin.mjs --help`. Apply the current schema before replay. Supply protected `QM_RESTORE_CLUSTER`, `QM_RESTORE_MEDIA_BUCKET` and `QM_RESTORE_CONFIRM=isolated:<cluster>`; the tool checks the account, rejects live API/worker database targets, requires S3 public blocking, reads the independent current deletion ledger and purges restored rows and object versions. It never enables public access. Before cutover, freeze mutations and replay a fresh ledger, exclude backups beyond the 90-day horizon, remove expired original/export copies, verify referenced media and both tenant boundaries, measure the accepted RPO/RTO, and only then separately authorize access. Unit replay tests are not a completed AWS snapshot restore drill.

Remaining acceptance work includes human password/TOTP enrollment, real iPhone Safari/Android Chrome permission/interruption tests, timed database-and-media restore, cross-region recovery rollout, broader model quality evaluation and church acceptance. Production requires a separately bootstrapped account. Compliance holds, native/offline clients, full ledger integration, barcode scanning and natural-language estate queries remain future product scope rather than disabled controls in the current site.

## What is implemented

- Invitation-only Cognito infrastructure, authenticator-app MFA required, classic hosted UI on the Lite tier, authorization code + S256 PKCE. No password handling in Quartermaster.
- A same-origin backend-for-frontend. Random single-use login state is bound to a separate browser cookie and a ten-minute DynamoDB record. ID/access signatures, issuer, client, token type, expiry, subject and nonce are checked. Only a random `__Host-` Secure/HttpOnly/SameSite cookie reaches the browser; its hash identifies a server session. No JWT/refresh token is stored in browser storage or returned by the API.
- Fixed sessions of at most one hour, with no refresh tokens retained. Cognito can reuse its own hosted-UI SSO session; the original `auth_time` is retained. Signing out revokes the current Quartermaster session, not every device or Cognito's SSO cookie. Revoke database membership for immediate tenant-access removal; disabling Cognito alone is not an immediate revocation of existing Quartermaster sessions.
- Exact-origin and synchronizer-token CSRF checks for authenticated mutations. Responses are `no-store`; errors contain safe codes and random request IDs, not SQL/content/tokens. Health and anonymous requests do not wake Aurora. No scheduled database polling is introduced.
- Current database memberships and four explicit capabilities: `assets:read`, `assets:write`, `maintenance:write`, `audit:read`. All tenant tables force RLS; runtime credentials cannot own tables, bypass RLS, or grant memberships. Real-data tenants fail closed. The operator has no automatic application membership or standing support access.
- Persistent asset create/read/update, bounded literal search across names/location/nameplate/notes, status filtering, cursor pagination, nameplate fields and free-text location/field notes. Location hierarchy, extensible class templates and asset disposal are later work.
- Maintenance task creation, status/due-date/notes updates through the API, UI task creation/status transitions, and append-only human-reported readings. Estate totals include attention, open work and overdue dates (UTC date boundary). A reading is not a safety instruction or AI-certified measurement.
- Private, server-saved capture drafts with version checks and atomic draft-to-asset commit. Incomplete drafts are allowed; committed assets must pass the full schema. Draft content is in PostgreSQL, under the database backup policy, not only in TTL session storage.
- Transactional content-free audit and mutation fingerprints. Every write requires a UUID idempotency key; updates/commits also require `If-Match: "version"`. Retries return the current authorized record with `replayed: true`, not an old content-bearing response. A changed request with the same key fails. No asynchronous effects are exposed yet, so no outbox is claimed as implemented.
- Online-only responsive forms, read-only memberships, organization selection, stale-edit feedback, unsaved-input warnings, manual session refresh and bounded foreground retries. Nothing is queued offline or saved merely because it appears on screen. A lost save acknowledgement reuses the same key. Draft edits must be saved before committing the draft, so an uncertain commit can be retried directly.
- Separate operator tooling for checksummed transactional migrations, an initial non-owner runtime credential, synthetic membership grants/revocation, and an unscoped RLS smoke check. It is not included in the deployed Lambda zip. Membership changes record the operator's opaque AWS principal ID and target subject ID, not email/passwords.

## API contract

All paths are same-origin. There is no cross-origin browser API. JSON input contracts are in `packages/contracts/src/index.ts`; unexpected properties and overlong input are rejected. Requests are limited to 16 KB; lists return at most 50 items plus `nextCursor`. Cursors are opaque UUID record IDs ordered ascending, not snapshot-consistent exports or chronological audit ordering. Search is a parameterized literal substring, not SQL or an AI query language.

| Path | Method | Result / input |
| --- | --- | --- |
| `/api/health` | GET | No-dependency liveness/configuration, release SHA; not a database readiness probe |
| `/api/auth/login` | GET | Begin PKCE redirect |
| `/api/auth/callback` | GET | Consume bound code/state, set session cookie, redirect to `/` |
| `/api/auth/session` | GET | Signed-in state, CSRF token, expiry, current memberships; no identity tokens |
| `/api/auth/logout` | POST | Revoke current session; Origin + CSRF required |
| `/api/v1/me` | GET | Current memberships |
| `/api/v1/tenants/{tenant}/assets` | GET / POST | `AssetPage` / `AssetInput`; GET accepts `q`, `status`, `cursor` |
| `…/assets/{id}` | GET / PATCH | `Asset` / complete `AssetInput` replacement of editable fields |
| `…/assets/{id}/maintenance` | GET / POST | Paged tasks / `MaintenanceInput` |
| `…/maintenance/{id}` | PATCH | Complete `MaintenanceInput`; optimistic version required |
| `…/assets/{id}/readings` | GET / POST | Paged readings / `ReadingInput`; future observations >5 minutes rejected |
| `…/drafts` | GET / POST | Current actor's paged drafts / partial `AssetInput` |
| `…/drafts/{id}` | PATCH | Replace draft content, with version |
| `…/drafts/{id}/commit` | POST | Empty JSON object and draft version; returns created asset |
| `…/summary` | GET | Total assets, attention count, open/overdue tasks |
| `…/audit` | GET | Paged content-free events; `audit:read` required |

Domain writes return `{ item, replayed }` after transaction commit. No DELETE route is enabled. A pending purge policy returns `409 purge_policy_pending`; it does not pretend to delete content. HTTP 401 means no valid session, 403 means missing capability/membership/CSRF or disabled real-data intake, 409 covers conflicts, 428 requires a version, and 503 indicates bounded retry is appropriate. Errors use problem JSON with `code` and `requestId`. No export, bulk operation, policy administration or support elevation needing recent authentication is exposed.

## Activation and account-setup runbook — do not run as ordinary CI

1. Validate locally: `pnpm verify`, `pnpm infra:check`, `pnpm test:e2e`, `pnpm audit --audit-level high`. Review changes, then publish the code through the existing dev pipeline with the workspace disabled. No migrations run in the application deployment role.
2. In protected delivery inputs, set `enable_identity=true`, keep `enable_workspace=false`. Review a fresh saved Terraform plan and its guardrail output before applying it. This creates only the invitation-only pool/client/domain and an **empty** secret container. It does not create a login. Cognito default email is for low-volume development; production sender setup is separate.
3. Use the local `default` profile and Node 24, from the repository root. Build with `pnpm build`. Set `QM_EXPECTED_ACCOUNT_ID` to the verified development account. Every operator invocation additionally requires `QM_OPERATOR_CONFIRM=quartermaster-dev:<command>`; then run `node services/core-api/dist/workspace-admin.mjs <command>`.
4. Run `migrate`, then `credentials`, then `check`. These are explicit operator actions and can wake Aurora. The migration ledger checks SHA-256 checksums, rejects unknown/modified applied migrations, serializes execution, and rolls back the whole transaction on failure. Do not use it to adopt an already hand-created schema: inspect/adopt that separately. Migration 0003 gives only the migration owner an explicit RLS policy for setup/recovery; Aurora's migration user is not a superuser. The application role cannot inherit that owner. A cold database may require rerunning after it resumes; never add a recurring wake-up job.
5. `credentials` creates the `qm_runtime` login with only inherited `qm_app` access and writes its generated password to the Terraform-owned runtime secret, not Terraform state or command arguments. An interrupted initial setup reuses the `AWSPENDING` version, including AWS's first-version case where that same version also carries `AWSCURRENT`. Any other existing current credential is refused; rotation requires a separate reviewed process. The command checks the live workspace is disabled. Runtime and managed migration secrets must remain separate. Secret operations use the AWS SDK with explicitly resolved default-profile credentials; only non-secret metadata travels in CLI arguments.
6. When the owner is ready, invite the chosen user through Cognito and complete password/TOTP setup. Obtain that pool's immutable user `sub`. This step was intentionally **not performed**. No operator script sends email or creates users.
7. For `grant`, supply `QM_USER_POOL_ID`, `QM_COGNITO_USERNAME`, `QM_ACTOR_ID` (matching `sub`), `QM_TENANT_ID` (new UUID), `QM_TENANT_NAME` (synthetic workspace only), and explicit comma-separated `QM_CAPABILITIES`. Default capabilities are read-only. Grant verifies the existing Cognito identity and inserts/updates a synthetic membership; it is not an invitation. `revoke` uses the same identity/tenant inputs, immediately disables that membership, and audits the change. Neither creates support access to a real church.
8. Run `integration` against actual Aurora/Data API before workspace activation. It creates two fresh temporary synthetic tenants and fabricated subject UUIDs, tests role/tenant denial, assets/tasks/readings/drafts, retry/version guards, timestamps/JSONB decoding, revocation and rollback, then removes only its own fixtures. No Cognito users, invitations or browser sessions are created, so this can precede the deferred account/membership steps 6–7. Lost-response behavior is separately tested in the browser suite; do not infer a successful live Cognito login from database checks.
9. Set `enable_workspace=true` in a newly reviewed delivery plan. Runtime IAM is limited to the exact database, runtime secret and auth-prefixed items in the existing on-demand session table. Lambda uses 256 MB, 30 seconds and at most five concurrent executions; no warm capacity. The deploy job receives `QM_EXPECT_WORKSPACE=true`. Terraform updates configuration; the pipeline still owns the live code alias. Release checks require the expected synthetic mode, unsigned session response and anonymous asset denial without database probes.
10. Run `QM_EXPECTED_RELEASE=<exact-commit> node tools/verify-workspace.mjs` after building the matching web files. It checks the live anonymous and provider-entry boundaries without creating an account. After the owner authorizes account setup, verify a successful Cognito login, password/TOTP enrollment, logout, expired-session recovery, cold start and phone/desktop saves. No actual phone camera test is implied. Roll back with the prior Lambda alias/web index; keep additive schema changes. Turning off the workspace is not permission to delete pools, secrets, memberships or data.
